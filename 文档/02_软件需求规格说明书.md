# 软件需求规格说明书

文档 ID：SRS · 版本：1.0 · 需求负责人：工作室业务负责人 · 工程基线：2026-09-18。项目：品牌「弈星纪元兽装工作室」，经营主体「弈星纪元（上海）文化发展有限公司」，域名 `starium.cn`，积分名称「星绒币」（C01/C15/C26）。

## 项目目的

访客可以判断工作室风格与接单能力，用户可以提交委托并跟踪制作，也能直接购买在售商品。运营人员在同一后台处理内容、报价、订单、售后和反馈。支付、积分与用户身份均保存在服务端，避免依赖客服手工对账或浏览器本地状态。

## 人员与权限边界

| 角色 | 可执行工作 | 数据范围 |
|---|---|---|
| visitor | 浏览已发布内容、商品、名额规则 | 公开内容 |
| customer | 手机号登录、自己的询价/订单/支付/反馈/积分/售后 | 仅本人；服务端逐对象检查 |
| content_editor | 编辑、预览、发布作品和公告 | 无手机号明文、订单金额修改权 |
| support | 查看分配的询价和售后、回复反馈 | 必要联系方式，默认脱敏 |
| maker | 查看分配给自己的制作单、更新制作节点 | 必要设定及量体数据；无支付密钥和退款权 |
| finance | 查询账单、审核退款、执行对账 | 必要交易与收款数据 |
| admin | 账号停用、角色分配、系统配置、异常处置 | 权限变更及导出均审计；不能覆盖账本 |

后台使用显式权限码而非单一 `is_admin`。内容发布、报价发布、退款申请、退款批准、积分调整分别授权。小团队可一人兼任角色，但退款申请与批准的分离要求由 C21 定义；身份相同不能被两个角色绕过。

## 用户场景

**UC-01 自设委托**：访客查看作品与规格 → 登录 → 阅读委托范围 → 上传设定并提交 → 收到补件或报价 → 在有效期内接受 → 确认条款 → 付预付款 → 查看制作并确认节点 → 付尾款 → 收货 → 满足奖励条件后获得积分。

**UC-02 购买现货**：浏览商品 → 选 SKU 和数量 → 购物车 → 地址与运费 → 确认金额 → 支付 → 物流 → 收货与售后 → 积分入账。库存不足、价格变化和支付结果未知各有独立恢复入口。

**UC-03 反馈奖励**：登录 → 提交可复现问题或具体建议 → 工作室受理 → 补充信息或审核 → 告知结论 → 符合标准则写入奖励流水。用户可申诉，不要求公开好评。

**UC-04 财务纠错**：对账发现多付款 → 关联渠道流水 → 自动标记异常 → 财务审核原路退款 → 查证到账 → 留痕。禁止手改订单为“已支付”掩盖异常。

**UC-05 洗毛预约**：访客在 `/wash` 比较单头/半装/全装洗护套餐 → 登录 → 填写部件、期望日期（不早于今日+2）与返还方式（到店取回/寄回）→ 提交预约 → 工作室确认档期并报价 → 有效期内下单付款 → 到店交付或寄出 → 洗护与检查 → 取回或寄回 → 完成后按实付发放星绒币。预约本身不收款，未审批通过不能直接购买服务。

**UC-06 公开参考估价**：访客在 `/estimate` 查看系列起价 → 选择系列/风格/加项 → 看到实时参考区间 → 填写称呼、联系方式、角色说明并勾选隐私 → 提交（无需登录）→ 获得编号与 3 个工作日回复承诺 → 工作人员联系并转为正式询价/报价。估价请求不收款、不锁库存、不直接生成订单。

## 非功能需求

以下为验收目标，不是已测性能或商业保证。流量、预算与目标经 C22/C25 确认后固化。

| ID | 指标 | 验证条件 |
|---|---|---|
| NFR-01 | 月可用性目标 99.5% | 用外部探针统计用户关键路径；维护停机也记录 |
| NFR-02 | 公共页面 LCP ≤2.5s、CLS ≤0.1、INP ≤200ms | 移动端真实样本 P75；上线前用约定设备和网络实验指标作代理 |
| NFR-03 | 常规读 API P95 ≤300ms，业务写 API P95 ≤700ms | 起测环境 2 vCPU/4GB/SSD，50 并发混合负载 15 分钟，剔除第三方等待但单独报告 |
| NFR-04 | 金额、库存、积分无重复/丢失 | 并发与故障注入测试；不能用平均成功率替代一致性 |
| NFR-05 | RPO ≤15 分钟，RTO ≤2 小时 | 从离机备份恢复至隔离环境并完成支付对账 |
| NFR-06 | 键盘可用，正文对比度 ≥4.5:1 | 关键流程人工检查；减弱动效开关生效 |
| NFR-07 | 手机 360px 至桌面 1440px 可用 | 无阻碍交易的横向溢出；错误与焦点可定位 |
| NFR-08 | 依赖边界无环，模块能独立测试 | 架构检查与跨模块契约测试 |
| NFR-09 | 手机号/地址/设定图不进公开日志和搜索引擎 | 日志抽查、对象存储权限及 CDN 缓存测试 |

## 约束与范围控制

首发基线为中国大陆（简体中文 / 人民币）与美国（美式英文 / 美元）双区并行、自营业务（C02/C24）。是否启用扩展只依《功能确认清单》，不能把表中 MAY 删除成“无需考虑”。不引入自建钱包、充值余额、积分提现、二级交易市场、平台商户入驻或自动信用分期。

需求变更记录：`变更ID、来源、修改的FR、受影响API/表/状态/用例、迁移方式、负责人、确认日期`。财务或身份规则变化必须先修改唯一规则源，再修改代码和测试。项目工时待 I0 技术验证与内容清单完成后估算，不把 AI 生成速度当作工期承诺。
