# 数据模型与一致性约束

这是逻辑数据字典，尚未执行数据库迁移。实现时由 SQLAlchemy/Alembic 建表并用约束测试验证，不能把本文件当成已部署数据库。

## 通用约定

公共主键用 UUID 字符串，内部排名序号可用单调整数。业务时间以 UTC 存整数毫秒或统一 ISO 字符串，整个项目只能选一种持久格式；API 统一返回带 `Z` 的 ISO 8601，默认显示 Asia/Shanghai。I0 基线选择 UTC 毫秒 INTEGER。

金额 `_cents INTEGER`，积分 INTEGER，布尔 INTEGER + CHECK，枚举 TEXT + CHECK。业务表通用 `id、created_at、updated_at、version`；账本、回调和审计只追加，不强行套可编辑时间字段。金额与数量有非负及上限检查。JSON 只用于内容块、不可变快照和已校验元数据，不能替代需要检索/约束的外键字段。

手机号规范化为 E.164；保存随机化加密密文用于通知，另用独立密钥 HMAC 的 `phone_lookup` 唯一索引查找。不可用普通 SHA256 对低熵手机号脱敏。密钥有 `key_version`，加密与查找密钥分离。财务/订单数据禁止级联删除。

## 事务不变量

1. 用户登录验证：消费 challenge + 建号/查号 + 新 session 在一次事务中；手机号唯一冲突按已有账号重读。
2. 创建订单：幂等登记 + 订单/行/付款项 + 库存或名额预留一并提交。
3. 处理成功付款：去重事件 + 收款 + 分配 + 应付状态 + 库存/名额 + outbox 一并提交。
4. 退款成功：退款状态与成功分摊 + outbox 同事务；积分消费者失败可重试，不撤销真实退款。
5. 积分入账：去重记录 + ledger + account 缓存 + award posted_points 同事务；退款和发奖锁定同一来源并重算目标，不信任旧事件携带的金额。
6. 反馈奖励：审核决定 + 奖励命令/outbox 同事务。预算扣占原子化，重复审核不能重复消耗预算。
7. 洗毛预约：校验商品已发布且 `service_kind=cleaning`、日期窗与返还方式 → 写申请；预约不占用 SKU 库存、不收款，审批通过后才允许按报价下单，库存与金额仍由订单事务裁定。

数据库 CHECK 保证行内约束，跨行总额由 service 在写事务中检查并通过并发测试验证。不要把所有跨行规则声称为 SQLite CHECK 已自动保证。

## 迁移与恢复

每次模型变化配 Alembic revision；SQLite 改列使用经过测试的 batch migration。先备份并在副本上跑升级、`foreign_key_check`、`integrity_check`、订单金额与积分汇总校验。线上禁用 `create_all` 代替迁移。

采用 expand → backfill → switch → contract；先加可空列并双读兼容，分批补数，完成验证后才收紧约束。有新交易写入后不能直接恢复旧备份充当普通回滚。迁移/恢复完整操作见 14。
