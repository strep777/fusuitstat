# 测试计划与验收用例

本文件是测试规格，尚未对网站实现执行这些用例。上线报告应填写实际结果、证据位置、执行环境和版本；不能把文档存在标为测试通过。

## 测试层级

领域单元测试覆盖状态机、金额、积分、期限和权限规则；集成测试使用真实 SQLite 临时文件和独立连接，不能用只在单连接内工作的内存库证明并发正确。适配器契约测试以渠道文档/已验证测试向量为依据，覆盖签名、时间戳与错误码。浏览器测试覆盖桌面、手机尺寸以及真实目标微信 WebView 的关键支付场景。

交易与身份核心分支必须有具体断言；覆盖率数字不替代业务证据。建议核心模块分支覆盖率目标 90%，其余不为凑数字写镜像实现测试。每个安全漏洞修复保留失败案例和回归测试。

## 身份、文件与权限

| ID | 操作 | 预期 |
|---|---|---|
| TC-A01 | 同手机号密集发短信，换 IP/重启服务再试 | 多维限流仍有效，验证码不在日志，费用熔断可观察 |
| TC-A02 | 错码、过期码、旧重发码、不同用途码 | 全部拒绝；失败计数不被重建挑战绕过 |
| TC-A03 | 两连接同时验证一个有效 OTP；登录前后比会话 | 只一次消费；session 轮换；退出后旧 token 失效 |
| TC-A04 | 用户 A 读/改 B 的订单、反馈、量体、地址、图片 | 拒绝且不泄露内容；更换随机 ID 无效 |
| TC-A05 | 编辑员直接调用退款/导出/角色授权 API；管理员未 MFA | 服务端拒绝；不可通过 UI 隐藏代替授权 |
| TC-A06 | 跨域伪造 POST、恶意 returnTo、会话过期时提交 | CSRF/open redirect 被拒；用户输入可安全恢复 |
| TC-A07 | 旧号丢失申诉、已回收手机号新设备登录 | 不凭订单号换绑；异常时不泄露历史私密资料 |
| TC-U01 | 假 PNG、脚本 SVG、超大像素、压缩炸弹、伪 complete | 隔离/拒绝，扫描完成前不可引用；无可执行内容 |
| TC-U02 | 私密链接过期、未授权访问、撤回展示授权 | 不再签发新链接；公开缓存按流程清除 |

## 委托与订单

| ID | 操作 | 预期 |
|---|---|---|
| TC-C01 | 草稿刷新、提交网络失败、重复提交、补件/撤回 | 保存版本明确、重复请求同一对象、终态不可越权修改 |
| TC-C02 | 接受过期/旧版报价；两标签同时接受 | 前两者拒绝，后者只一个订单与名额预留 |
| TC-C03 | 接受条款后管理员发布新版，查询旧订单 | 原版本、金额与同意证据仍完整 |
| TC-C04 | 两用户争最后名额，期限边界提交，延迟支付 | 容量不超，服务端时间裁决，晚款进入异常处置 |
| TC-C05 | 装师上传新阶段图后客户确认旧版 | 409；变更收费需客户接受，不覆写原价 |
| TC-O01 | 客户改价、负数量、失效地址、下架 SKU | 服务端拒绝或要求重新确认，订单金额正确 |
| TC-O02 | 50 并发购买最后一件/独占角色 | 最多一份有效占用，库存不负，没有双卖 |
| TC-O03 | 关单释放与付款通知同时发生，进程中途退出 | 要么消费预留，要么关闭后记异常款；两者不同时成功 |
| TC-O04 | 修改地址、重复发货、退款后回库、发票申请 | 原始快照保留；状态合法；无自动错误回库 |

## 支付与退款

| ID | 操作 | 预期 |
|---|---|---|
| TC-P01 | 正常全款/预付款/尾款与取消支付 | 只有真实成功款入账，未付尾款不能发货 |
| TC-P02 | 同一通知发送 10 次，业务 outbox 消费 10 次 | 收款/库存/积分各产生一次业务效果 |
| TC-P03 | 错签名、过期重放、未知证书序列、解密失败 | 不入账，记录安全事件；不回显秘密 |
| TC-P04 | 签名合法但商户/app/币种/金额不匹配 | 隔离和告警；不为目标订单发货 |
| TC-P05 | 渠道下单超时但真实已建单 | UNKNOWN，同商户单号查询，不重复收款 |
| TC-P06 | 回调先于下单响应、成功后又收到旧失败状态 | 成功不可回退，金额只分配一次 |
| TC-P07 | 两渠道均真实付款、旧二维码迟到支付 | 两笔款都留账，多付部分进入退款，订单正常已付额不翻倍 |
| TC-P08 | 丢失回调、账单多一笔/少一笔、服务重启 | 主动查单/日对账发现并处置，差异可追踪 |
| TC-P09 | 两客服并发退同一笔款、退款超时后重试 | 总退款和预留不超过原收款，同退款号查证 |
| TC-P10 | 多次部分退款，混含运费、商品优惠、多付退款 | 分摊总和与渠道退款一致；多付退款不冲正常实收 |
| TC-P11 | 已退款通知重复、退款先到积分发奖后到 | 只一笔退款效果，积分以当前净额为准 |

## 积分、反馈与任务

| ID | 操作 | 预期 |
|---|---|---|
| TC-L01 | 定制首期/尾款分次支付、完成后待入账 | 按整个订单净商品金额计算，只一个 award |
| TC-L02 | 按 09 文档全部数值例子测试部分退款 | 199 分两次退款边界正确，运费不计奖 |
| TC-L03 | 积分已花完再退款，后续又获奖励 | 可负账面、可用不负；现金退款不受阻 |
| TC-L04 | 并发发奖/退款、任务崩溃、重建缓存 | 流水总和=账户缓存；重启无重复或漏发 |
| TC-F01 | 有效负面反馈、重复建议、无价值刷屏 | 奖励按质量判断，有理由和申诉，不诱导好评 |
| TC-F02 | 两审核人同时批准、同反馈升级奖励 | 一次来源奖励，升级只补差额，预算不超 |
| TC-F03 | 跨日/月边界提交、预算耗尽仍反馈 | 时区正确；正常受理但说明奖励限制 |
| TC-R01 | worker 领取后崩溃、通知供应商失败 | 租约到期重领，退避/死信生效，交易不回滚 |
| TC-R02 | 备份期间持续写入，恢复到新主机 | integrity/外键/金额/积分校验通过，实测 RPO/RTO |
| TC-R03 | 新版发布失败、迁移后回滚、恢复后的渠道对账 | 不覆盖新交易，旧应用兼容或正向修复，账务对齐 |
| TC-R04 | 50 并发混合流量压测 15 分钟及长连接读 | 达 NFR 或提出有数据的容量调整；无金额库存错误 |

## 界面与内容验收

每个公共/客户/后台路由测试直接打开、刷新、返回、窄屏、无数据、接口错误和过期会话。检查指定三组素材、图像比例、低对比度背景、减少动效、键盘焦点、表单可读错误。检索引擎只能获得已发布内容；无权访问页面不应返回私密 OG 信息。

可选 C11/C15/C16/C20/C24/C29 的功能分别增加测试，不开启则验证入口隐藏且后端拒绝。未启用功能不被要求通过它的成功路径，但不能存在绕过开关的 API。

## 商业上线验收表

- [ ] I0–I5 的 MUST 需求实际通过，并附 commit/版本和测试报告。
- [ ] 支付和短信至少一个真实开通渠道经受控验收；没有开发桩进入生产。
- [ ] 所有金额、库存、名额、积分关键不变量用并发/故障测试验证。
- [ ] 无未处理的高危安全缺陷；中低风险有负责人和期限。
- [ ] 隐私、合同、经营信息、售后及素材授权按确认清单完成。
- [ ] 离机恢复演练成功，支付恢复对账完成，值班人可接告警。
- [ ] 运营人员能独立发布商品、报价、发货、退款、处理反馈和查看审计。
- [ ] 实际容量和失败恢复满足已确认目标；上线范围与功能开关留证。

报告模板：`测试ID / 环境与版本 / 前置数据 / 操作 / 预期 / 实际 / PASS或FAIL或BLOCKED / 证据路径 / 缺陷编号 / 执行人和日期`。BLOCKED 不算 PASS。
