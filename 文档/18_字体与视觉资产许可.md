# 字体与视觉资产许可（2026-11）

本文件记录本站字体、图标与视觉素材的许可结论。**规则：随站点分发的前端字体文件只允许 MIT 许可。**

## 1. 结论先行

1. 本站随构建包分发的唯一字体是 **Hack**（MIT），放在 `web/public/fonts/hack/`，用于拉丁字母、数字、价格、编号、代码与技术标签。
2. 中文正文与标题**不随站点分发字体文件**，由浏览器在 Hack 缺字时自动回退到访问者系统的中文黑体。CSS 字体栈只声明 MIT 的 Hack 与通用族名，不声明任何具体商业中文字体。
3. 站点不加载 Google Fonts、字体 CDN 或任何第三方远程字体，避免隐私、可用性与许可漂移。
4. **不存在可商用、高质量、覆盖简体中文的 MIT 字体**。若未来要求“中文也必须是开源字体文件”，只能改用 OFL-1.1 的思源/Noto 系列，需要需求方明确批准；在批准前不引入。

## 2. 调研记录

| 字体 | 许可 | 结论 |
|---|---|---|
| Hack | MIT | 采用，仅拉丁/数字/符号 |
| Cascadia Code | OFL-1.1 | 不采用（不是 MIT） |
| Noto Sans SC / 思源黑体 | OFL-1.1 | 不采用（不是 MIT） |
| 霞鹜文楷 LXGW WenKai | OFL-1.1 | 不采用（不是 MIT） |
| 文渊 / 京华老宋 | OFL-1.1 | 不采用（不是 MIT） |
| Zpix 最像素 | 商用付费 | 不采用 |
| Inter / Manrope / Space Grotesk | OFL-1.1 | 不采用 |
| 系统中文黑体（苹方、微软雅黑等） | 随系统授权，不随本站分发 | 作为中文回退，不打包、不宣称开源 |

说明：部分 npm 字体包在 `package.json` 写 MIT，但包内字体文件仍携带 OFL 文本，属于包装层与字体许可不一致；本站以**字体文件自带的 LICENSE** 为准，不以 npm 元数据为准。

## 3. 落地方式

```text
web/public/fonts/hack/
  Hack-Regular.ttf
  Hack-Bold.ttf
  LICENSE.md          # 上游 MIT 原文
  SOURCE.txt          # 上游地址、版本、下载日期、SHA256
```

- CSS：`@font-face` 两个字重，`font-display: swap`；只声明 `"Hack"` 与通用族名，中文缺字由浏览器回退。
- 预加载：只预加载 `Hack-Regular`，避免首屏多请求。
- 字体栈：`--font-sans`、`--font-display`、`--font-mono` 均为 `"Hack", <通用族名>`，不写具体中文字体名。
- 后台表格、金额、订单号、权限码使用 Hack，提高对齐与扫读效率。
- 字体只用于界面，不用于 Logo 图形；Logo 继续使用品牌 manifest 指定的 PNG。

## 4. 许可合规

- MIT 允许商用、修改与再分发，前提是保留版权声明与许可文本。仓库内保留上游 `LICENSE.md`，构建产物不删除该文件。
- 不修改字体名称后冒充自有字体；如需子集化，保留原始版权与许可，并在 `SOURCE.txt` 记录子集命令。
- 系统中文回退字体不复制、不打包、不通过 `@font-face` 分发，因此不构成再分发。
- 参考站点的图片、Logo、人物照片、文案一律不下载使用；视觉参考只提炼布局与信息层级。

## 5. 验收

1. `web/public/fonts/hack/` 存在且只含 MIT 字体与许可文件。
2. 全站源码无 `fonts.googleapis.com`、`fonts.gstatic.com`、`@font-face` 指向第三方 URL。
3. 构建产物中字体请求只命中 `/fonts/hack/*`。
4. `SOURCE.txt` 的 SHA256 与文件一致。
5. README 与设计文档写明「中文使用系统字体栈，不分发中文字体」这一限制。

## 6. 变更流程

新增字体必须同时提交：字体文件、上游 LICENSE、来源与版本、SHA256、使用范围、对中文回退的影响。许可不是 MIT 的字体不得进入 `web/public/fonts/`；如业务确需 OFL 中文字体，先更新本文件并取得需求方书面确认，再改构建与 README。
