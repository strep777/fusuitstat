# 防爬虫、高并发与数据安全设计（2026-11）

状态：应用层守卫已实现（2026-11-04，`server/app/platform/guard.py`、`server/tests/integration/test_request_guard.py`、`test_security_headers.py`）；CDN/WAF 与 50 并发容量仍未验收，代码实现与验证结果见 `文档/17_交付检查与后续记录.md`。本文是安全与容量行为的单一规则源；实现不得超出本文声明的保护范围对外宣称“已防住”。

## 1. 目标与非目标

### 目标

- 公开内容可被正常搜索、分享和人工访问，**不被批量抓取拖垮**。
- 突发流量、脚本刷接口、慢请求、超大请求体不会耗尽数据库连接或工作进程。
- 登录、下单、支付、后台等敏感路径有独立的、更严格的限额与审计。
- 数据最小化：限流键、日志、监控不保存 IP/手机号/会话明文。
- 在单机 SQLite 架构下给出可验证的降级行为：超限返回 429、过载返回 503，并带 `Retry-After`。

### 非目标（不得宣称）

- 不替代 CDN/WAF：应用层只能处理到达进程的流量。
- 不保证抵抗 TB 级 DDoS、Botnet 或平台级 CC；这些必须由云防火墙/清洗中心承担。
- 不承诺 50 并发下的商业容量 PASS；容量验收需要独立压测环境，见第 9 节。
- 不做“永久封 IP”的自动处置；只做短窗口限速与可审计的临时封禁。

## 2. 威胁模型

| 威胁 | 场景 | 主要控制 |
|---|---|---|
| 批量爬取目录/作品 | 脚本遍历 `/products`、`/works`、`/news`，放大数据库查询 | 匿名读限额、分页上限、`robots.txt`、UA/空 UA 拒绝、蜜罐 |
| 撞库/验证码轰炸 | 批量手机号请求短信、尝试登录 | 既有手机号/IP/每日预算限额 + 全局登录限额 + 审计 |
| 接口枚举 | 遍历订单号、退款号、角色 slug | 资源随机 ID、权限校验、404 统一、写接口限额 |
| 请求体炸弹 | 超大 JSON/multipart 占满内存 | `Content-Length` 上限、流式读取上限、413 |
| 慢连接/慢请求 | 大量 keep-alive 或半开连接 | Uvicorn `--timeout-keep-alive`、反向代理超时、并发闸门 |
| 缓存穿透/雪崩 | 高频请求不存在的 slug | 统一 404、短 TTL 公共缓存、查询上限 |
| 后台暴力破解 | 撞员工密码/MFA | 既有登录限流与锁定、后台独立限额、可选 IP 允许清单、MFA |
| 数据泄露 | 日志/错误响应/缓存泄露个人信息 | 脱敏日志、统一错误结构、私有接口 `no-store`、CSP/安全头 |
| 爬虫伪装 | 伪造 Googlebot UA | 只按 UA 做粗筛，不把 UA 当身份；真实校验交给边缘网关 |

## 3. 分层控制

```text
CDN / WAF / Nginx        连接数、TLS、静态缓存、地域/速率规则、Bot 规则
        ↓
Uvicorn                   keep-alive 超时、并发上限、请求行/头大小
        ↓
应用 Guard 中间件          请求体上限、并发闸门、IP/UA 粗筛、全局限额、缓存头
        ↓
业务限额                 短信/登录/反馈/上传等既有 SQLite 原子限额
        ↓
数据库                    WAL、busy_timeout、短事务、条件更新、索引
```

应用层 Guard 是**最后一道**，不是唯一一道。生产必须在 Nginx/云 WAF 再配置连接数与速率规则，参数见 `文档/14`。

## 4. 全局限额（应用层）

默认值按单进程设计；多 worker 时实际总限额 ≈ 单进程限额 × worker 数，部署时必须按此换算并在边缘收口。

| 作用域 | 键 | 默认限额 | 窗口 | 适用 |
|---|---|---|---|---|
| `global:ip` | IP 哈希 | 300 次 | 60s | 所有 `/api/v1` 请求 |
| `global:read` | IP 哈希 | 240 次 | 60s | GET/HEAD 公开读 |
| `global:search` | IP 哈希 | 90 次 | 60s | 带 `q` 的搜索与目录筛选 |
| `global:write` | IP 哈希 | 30 次 | 60s | POST/PATCH/PUT/DELETE |
| `global:admin` | IP 哈希 | 60 次 | 60s | `/api/v1/admin/*`（叠加后台登录限额） |
| `global:trap` | IP 哈希 | 3 次 | 24h | 蜜罐路径，超限直接 403 |

规则：

- 计数使用进程内固定窗口 + 分片字典，热路径不加数据库写；多进程不共享，按上表换算。
- 敏感业务（短信、邮箱验证码、后台登录、反馈、上传）继续使用 SQLite `rate_limit_buckets` 的原子计数，不能只靠内存。
- 返回 429 时带 `Retry-After`、`X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset`；错误体沿用 `RATE_LIMITED`。
- 测试环境（`APP_ENV=test`）默认放宽到不干扰功能测试；安全用例显式调低限额后验证。
- `TRUSTED_PROXY_IPS` 之外不信任 `X-Forwarded-For`；代理链必须由部署方保证只追加不覆盖。
- IP 只以 HMAC 哈希进入计数键与日志，不落明文。

## 5. 爬虫策略

### 5.1 允许

- 正常搜索引擎（Googlebot、Bingbot、Baiduspider、Sogou、360）可抓公开页面；仍受匿名读限额约束。
- 社交平台预览、RSS/公告抓取按普通匿名请求处理。

### 5.2 拒绝

生产环境对以下请求返回 403 `ROBOT_DENIED`（测试环境关闭，避免误伤）：

- 空 `User-Agent`。
- 已知漏洞扫描器：`sqlmap`、`nikto`、`nmap`、`masscan`、`acunetix`、`nessus`。
- 已知高侵略性采集/AI 抓取 UA：`semrush`、`ahrefs`、`mj12bot`、`bytespider`、`gptbot`、`ccbot`、`claude-web`、`amazonbot`、`petalbot`、`dataforseo`。
- 配置项 `CRAWLER_BLOCKLIST` 可追加逗号分隔关键字。

不按 UA 放行任何“伪 Googlebot”；需要验证时由边缘网关做反向 DNS/IP 校验，应用层不做。

### 5.3 robots 与蜜罐

- `web/public/robots.txt`：允许公开页面，禁止 `/admin`、`/account`、`/cart`、`/checkout`、`/pay`、`/api/`；声明 sitemap。
- `web/public/sitemap.xml`：只列公开静态路由，不含个人页与查询参数。
- 蜜罐：页面中一个视觉隐藏、`rel="nofollow"`、`aria-hidden` 的链接指向 `/api/v1/_hp`；命中即计 `global:trap`，超限 403，并记安全日志（哈希 IP、路径、UA 长度，不记 query）。
- API 响应加 `X-Robots-Tag: noindex, nofollow`；后台 SPA 已有 noindex meta。

## 6. 并发、请求体与超时

| 控制 | 默认 | 行为 |
|---|---|---|
| 应用并发请求 | 128 | 超出等待 80ms，仍无槽位返回 503 `SERVER_BUSY` + `Retry-After: 2` |
| JSON/表单请求体 | 1 MiB | `Content-Length` 超限直接 413 `PAYLOAD_TOO_LARGE` |
| 多部分上传 | 32 MiB | Guard 粗限；业务层再按单文件 10 MiB、3 个文件精确校验 |
| 请求头总大小 | 由 Uvicorn/代理限制 | 生产 `--limit-concurrency` 与代理 `client_max_body_size` 双保险 |
| keep-alive | 5s | Uvicorn 启动参数 |
| 数据库连接池 | 20 + 10 overflow | SQLite WAL；写事务短、`busy_timeout=5000` |
| 慢查询 | 目录查询上限 48 条/页 | 禁止无上限导出；后台分页 |

并发闸门只保护进程，不替代队列。持续过载时应扩容/限流，而不是把等待时间无限拉长。

## 7. 缓存与性能

- 匿名公开 GET（`/api/v1/products`、`/api/v1/products/{slug}`、`/api/v1/content/*`、`/api/v1/site/*`）允许 `Cache-Control: public, max-age=15, stale-while-revalidate=60`。
- 带会话 Cookie、`Authorization`、CSRF 或命中账户/订单/后台路径的响应一律 `no-store`。
- 写请求、支付回调、后台接口永不公共缓存。
- 启用 GZip（最小 1KB），压缩 JSON/HTML；图片由静态服务器/CDN 处理。
- 索引：商品 `status+category+sort_order`、`slug` 唯一、订单用户+时间、限流三元组唯一；迁移中补充缺失索引。
- 慢查询治理：列表强制 `limit<=48`，搜索 `q` 长度上限 64，禁止 `%` 前置模糊导致全表扫描。

## 8. 数据安全

- 密钥只从环境/密钥管理注入；生产启动校验长度与开发默认值，缺一项即拒绝启动。
- 仅 `APP_ENV=development` 且未注入密钥时，首次使用会在 `server/var/.dev-secrets.json` 生成本机密钥（权限 0600、已被 git 忽略），保证重启后仍能解密演示库；`test` 使用进程内随机值；staging/production 不落盘、缺失即失败。
- 手机号 HMAC 查找 + 加密保存；验证码只存 HMAC；会话只存哈希；日志禁止手机号、地址、验证码、Cookie、签名 URL、支付报文。
- 写请求校验 CSRF 与 Origin；Cookie `HttpOnly`、`Secure`（生产）、`SameSite=Lax`。
- 后台：MFA、会话 8h、审批职责分离、可选 `ADMIN_IP_ALLOWLIST`；后台响应 `no-store` 与 `noindex`。
- 安全响应头：CSP、HSTS（生产）、`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy`、`Permissions-Policy`、`Cross-Origin-Opener-Policy: same-origin`、`Cross-Origin-Resource-Policy: same-site`。
- 备份：每日全量 + WAL 归档，备份加密，恢复演练每季度；备份文件不放在 Web 根目录。
- 审计：后台写操作、审批、退款、权限变更、限流封禁事件写审计；审计不含明文 PII。

## 9. 容量与压测

NFR-03 目标：50 并发、持续 15 分钟、读 P95 ≤300ms、写 P95 ≤700ms、错误率 <1%。本地单机只能作为**回归基线**，不能替代生产容量验收（R28）。

压测协议：

1. 独立测试库 + `seed-demo`，关闭调试日志，固定 CPU/内存。
2. 预热 60s，正式采样 15min；记录 RPS、P50/P95/P99、5xx 率、429 率、SQLite `busy` 次数。
3. 读场景：首页聚合、商品列表、商品详情、作品列表；写场景：登录后加购/创建订单（沙盒支付）。
4. 结果写入 `文档/17`，注明机器配置、并发数、数据集大小；未达标不得写 PASS。
5. 本地快速回归：`python scripts/security_smoke.py --base-url http://127.0.0.1:8000 --path /api/v1/products --concurrency 8 --duration 15`，只用于发现退化，不作容量结论。

## 10. 降级与故障

| 情况 | 行为 | 运维动作 |
|---|---|---|
| 单 IP 超限 | 429 + Retry-After | 观察是否误伤 NAT/校园网，必要时调高或加白 |
| 全局并发满 | 503 + Retry-After: 2 | 检查慢查询/外部依赖；扩容或限流 |
| 数据库忙 | 请求失败 503/500，不返回半成品 | 检查长事务；WAL 与 busy_timeout |
| 限流存储不可用 | 敏感路径 fail closed（503），公开读 fail open 并告警 | 修复数据库；不得静默放行短信 |
| 爬虫洪峰 | 429/403，静态资源由 CDN 承接 | 边缘封禁、提高缓存命中 |
| 误封 | 提供 `support@starium.cn` 申诉；后台可查安全事件 | 复核哈希 IP 与 UA，不记录明文 |

## 11. 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `SECURITY_GUARD_ENABLED` | true | 总开关；生产不得关闭 |
| `MAX_CONCURRENT_REQUESTS` | 128 | 进程内并发闸门 |
| `CONCURRENCY_QUEUE_MS` | 80 | 排队等待上限 |
| `MAX_JSON_BODY_BYTES` | 1048576 | JSON/表单上限 |
| `MAX_MULTIPART_BODY_BYTES` | 33554432 | 多部分粗限 |
| `RATE_LIMIT_GLOBAL_PER_MINUTE` | 300 | 全局限额 |
| `RATE_LIMIT_READ_PER_MINUTE` | 240 | 读限额 |
| `RATE_LIMIT_SEARCH_PER_MINUTE` | 90 | 搜索限额 |
| `RATE_LIMIT_WRITE_PER_MINUTE` | 30 | 写限额 |
| `RATE_LIMIT_ADMIN_PER_MINUTE` | 60 | 后台限额 |
| `CRAWLER_BLOCK_ENABLED` | 生产 true / 测试 false | UA 粗筛 |
| `CRAWLER_BLOCKLIST` | 内置列表 | 追加关键字 |
| `ADMIN_IP_ALLOWLIST` | 空 | 非空时后台只允许这些 IP/CIDR |
| `PUBLIC_CACHE_SECONDS` | 15 | 匿名公开读缓存 |

浏览器 journey 在 `e2e/playwright.config.ts` 中显式设置 `SECURITY_GUARD_ENABLED=false`：同一 IP 的数百次请求会撞全站桶，测试会误判；守卫行为由 `server/tests/integration/test_request_guard.py` 覆盖。生产与普通开发默认仍为 true。
